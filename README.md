# 강의 보드 (Lecture Copy Board)

강의자가 적어 저장한 글을, 수강생이 다른 기기에서 실시간으로 보고 **복사 버튼** 한 번으로 클립보드에 담는 아주 단순한 웹앱입니다.

- **수강생 화면(기본):** 강의자가 올린 글이 최신순으로 쌓임. 드래그 선택 가능, 오른쪽 복사 버튼.
- **강의자 모드(비밀번호 필요):** 글 작성·저장, 수정, 삭제, 숨기기(개별/일괄).
- **수업 종류:** 강의자가 수업을 등록해두고 하나를 고르면, 그 수업의 글만 양쪽 화면에 표시됨.
- 단일 `index.html` 정적 페이지 → **GitHub Pages**로 무료 배포.
- 기기 간 실시간 동기화는 **Firebase Realtime Database**(무료)로 처리.

> ⚠️ **강의자 비밀번호는 "실수 방지"용이지 보안이 아닙니다.**
> 비밀번호는 평문이 아니라 해시(PBKDF2-SHA256)로만 저장되지만, 이 앱은 공개된 정적 페이지라
> 브라우저 개발자도구로 잠금을 우회하는 것은 누구든 가능합니다.
> 실제 데이터 보호는 Firebase 보안 규칙이 담당합니다. 민감정보는 올리지 마세요.

## 1. Firebase 설정 (최초 1회, 약 5분 · 무료)

정적 호스팅(GitHub Pages)에는 서버가 없기 때문에, 기기 간 실시간 공유를 위해 Firebase가 필요합니다.

### 1-1. 프로젝트 생성
1. https://console.firebase.google.com/ 접속 → Google 계정 로그인
2. **프로젝트 추가** 클릭 → 원하는 이름 입력 (예: `lecture-board`)
3. Google 애널리틱스는 **사용 안 함**으로 두고 생성해도 됩니다.

### 1-2. Realtime Database 켜기
1. 왼쪽 메뉴 **빌드 → Realtime Database** 클릭
2. **데이터베이스 만들기** 클릭
3. 위치는 기본값(또는 `asia-southeast1`) 선택
4. 보안 규칙은 우선 **테스트 모드로 시작** 선택 → 사용 설정
   - (테스트 모드는 일정 기간 후 잠기므로, 아래 1-4에서 규칙을 직접 지정하는 것을 권장)

### 1-3. 웹 앱 등록 후 config 복사
1. 상단 톱니바퀴 **프로젝트 설정** → 아래로 스크롤 → **내 앱** 에서 웹 아이콘 `</>` 클릭
2. 앱 닉네임 입력 후 등록 (Hosting은 체크 안 해도 됩니다)
3. 표시되는 `firebaseConfig` 객체를 복사

`index.html` 상단의 아래 부분을 **본인 값으로 교체**하세요:

```js
const firebaseConfig = {
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_PROJECT.firebaseapp.com",
  databaseURL: "https://YOUR_PROJECT-default-rtdb.firebaseio.com",
  projectId: "YOUR_PROJECT",
  storageBucket: "YOUR_PROJECT.appspot.com",
  messagingSenderId: "YOUR_SENDER_ID",
  appId: "YOUR_APP_ID"
};
```

> `databaseURL`이 config에 안 보이면 Realtime Database 페이지 상단에 표시된 URL
> (`https://...-default-rtdb.firebaseio.com`)을 직접 넣어주세요.

### 1-4. 보안 규칙 (권장)
Realtime Database → **규칙** 탭에서 아래로 설정하면 이 앱의 데이터만 읽고 쓸 수 있습니다:

```json
{
  "rules": {
    "rooms": {
      ".read": true,
      ".write": true
    }
  }
}
```

> 공용 게시판이라 읽기/쓰기를 공개로 둡니다. 강의자 비밀번호는 앱 화면 진입용이며 DB 규칙과는 별개입니다.
> 더 엄격히 하려면 Firebase Authentication을 붙이는 확장이 필요합니다(현재 범위 밖).

## 2. GitHub Pages 배포

1. GitHub에서 새 저장소 생성 (예: `lecture-board`) — Public 권장
2. 이 폴더의 `index.html`(Firebase config 교체 완료본)을 저장소에 올립니다.
   - 웹에서 **Add file → Upload files** 로 드래그해도 되고, git으로 push 해도 됩니다.
3. 저장소 **Settings → Pages**
4. **Build and deployment → Source** 를 **Deploy from a branch** 로,
   Branch를 **main / (root)** 로 지정 후 **Save**
5. 잠시 뒤 상단에 표시되는 주소로 접속:
   `https://<사용자명>.github.io/<저장소명>/`

이 주소가 **수강생용 주소**입니다. 그대로 공유하면 됩니다.

## 3. 사용 방법

### 수강생
- 배포된 주소에 접속하면 강의자가 올린 글이 최신순으로 보입니다.
- 글을 드래그해 선택하거나, 오른쪽 **복사** 버튼을 누르면 클립보드에 저장됩니다("복사됨" 표시).
- 강의자가 특정 수업을 선택해 두면 상단에 **현재 수업: ○○○** 이 표시되고, 그 수업의 글만 보입니다.

### 강의자
- 우측 상단 **강의자 모드** 클릭 → 비밀번호 입력
  - 입력창은 `•`로 가려집니다. **화면을 공유·송출 중에도 비밀번호가 노출되지 않습니다.**
- 상단 입력창에 글을 적고 **저장** (여러 줄 가능, `Ctrl/⌘ + Enter`로도 저장)
- 각 글 카드에서:
  - **수정**: 그 자리에서 고쳐 저장
  - **숨기기 / 보이기**: 삭제하지 않고 수강생 화면에서만 감추기/다시 보이기 (숨긴 글은 강의자 화면에 흐리게 표시)
  - **삭제**: 확인 후 완전 삭제
- 상단 **모두 숨기기 / 모두 보이기**: 전체를 한 번에 감췄다가 강의 흐름에 따라 하나씩 풀어 재사용
  - 수업 종류를 선택한 상태에서는 **그 수업의 글에만** 적용됩니다.
- **수강생 화면으로** 버튼으로 언제든 되돌아갈 수 있습니다.

### 수업 종류 (여러 수업을 한 보드에서 운영하기)
강의자 화면 상단의 **수업 종류 바**에서 관리합니다.

- **+ 수업 추가**: 이름을 입력해 수업을 등록합니다 (예: `파이썬 기초`, `데이터 분석`). 추가하면 바로 선택됩니다.
- **수업 선택**: 이름 버튼(칩)을 누르면 그 수업의 글만 남고 나머지는 화면에서 빠집니다.
  - 선택한 수업은 **수강생 화면에도 그대로 반영**됩니다. 강의자가 수업을 바꾸면 수강생 화면도 같이 바뀝니다.
  - **전체**를 누르면 모든 수업의 글을 한 번에 봅니다(수강생 화면에는 각 글에 수업 이름 배지가 붙습니다).
- **글의 수업 지정**: 입력창 아래 `수업 종류` 선택으로 새 글의 수업을 정합니다(선택 중인 수업이 기본값).
  이미 올린 글은 각 카드 안의 선택 상자로 언제든 다른 수업으로 옮길 수 있습니다.
- **이름 변경 / 수업 삭제**: 수업을 선택하면 오른쪽에 나타납니다.
  수업을 삭제해도 **글은 지워지지 않고 `미분류`로 이동**합니다.
- 수업을 지정하지 않은 글은 `미분류`이며, 특정 수업을 선택하면 화면에 나오지 않습니다.
  기존에 올려둔 글들도 모두 `미분류`로 시작하니, 필요하면 각 카드에서 수업을 지정해 주세요.

## 파일 구성
- `index.html` — 앱 전체(HTML/CSS/JS 인라인). 이 파일 하나만 배포하면 됩니다.
- `README.md` — 이 문서.

## 디자인 시스템

이 앱의 디자인은 [sehunYang.github.io](https://github.com/sehunYang/sehunYang.github.io)의 `css/main.css`를 기준으로 통일되어 있습니다.
`index.html`의 `<style>` 블록은 두 구획으로 나뉩니다.

- **`PORTABLE: TOKENS + PRIMITIVES`** — 색 토큰, 타이포, `.button` / `.icon-button` / `.notice` / `.toast`.
  다른 프로젝트에 같은 디자인을 입힐 때는 **이 블록만 복사**하면 됩니다.
- **`APP-SPECIFIC`** — 강의 보드 전용 규칙(버블, 수업 칩, 프로필 카드 등).

> ⚠️ 두 구획의 **순서를 바꾸지 마세요.** `.button`과 `.btn-primary`는 CSS 특이성이 같아 나중에 선언된 쪽이 이깁니다.
> APP-SPECIFIC이 앞으로 오면 저장 버튼이 회색으로 보이는 오류가 납니다.

**다크 모드**는 우측 상단 `◐` 버튼으로 전환하며, 선택은 브라우저에 저장됩니다.
처음 방문하면 운영체제 설정을 따릅니다. 테마 적용 코드는 `<head>`에 있어 사내망에서 Firebase가 차단돼도 정상 동작합니다.

## 커스터마이즈
- 비밀번호: 아래 **비밀번호 변경** 절차 참고 (평문이 코드에 없어 직접 수정할 수 없습니다)
- 글자 크기: 전체 배율은 `html { font-size: 17px; }` (모바일 16px), 버블 본문만 바꾸려면 `.bubble .text { font-size: 1.5rem; }`
- 색상: `:root`와 `[data-theme="dark"]`의 토큰(`--accent`, `--surface`, `--text` 등). 개별 규칙에 색을 직접 적지 말고 토큰을 고치세요.
- 글꼴: Pretendard Variable(웹폰트 CDN 자동 로드). 오프라인/사내망이면 폰트를 직접 내려받아 로컬 `@font-face`로 교체하세요.
  CDN이 막혀도 `--font`의 폴백(맑은 고딕 등)으로 표시됩니다.

## 비밀번호 변경

비밀번호는 평문이 아니라 **PBKDF2-SHA256(310,000회) 해시**로만 `index.html`에 들어 있습니다.
그래서 파일을 열어 직접 고칠 수 없고, 전용 도구로 새 값을 만들어 넣어야 합니다.

1. `비밀번호_변경.html` 파일을 **더블클릭해서 브라우저로 엽니다.**
2. 새 비밀번호를 입력하고 **코드 만들기**를 누릅니다.
3. 나온 코드를 복사합니다.
4. `index.html`에서 `const TEACHER_AUTH = {` 로 시작해 `};` 로 끝나는 부분을 찾아 **통째로 교체**합니다.
5. 저장 후 GitHub에 올리면 적용됩니다.

> 이 도구는 아무 데도 전송하지 않고 브라우저 안에서만 계산합니다.
> `비밀번호_변경.html`은 배포에 필요 없으니 GitHub에 올리지 않아도 됩니다.

### 어떤 비밀번호를 쓸까요

**숫자 4자리는 권하지 않습니다.** 해시로 저장해도 경우의 수가 1만 가지뿐이라
자동 대입으로 금방 뚫립니다. 한글이 섞인 **8자 이상**(예: `해송물리연수2026!`)을 권합니다.
길이가 곧 안전도이고, 어차피 자주 입력하는 값이 아닙니다.
